# => と -> の違い
まったく別物です。見た目が似ているだけで、用途に関連はありません。

## `->` は *「オブジェクトの中のものを使う」とき* に使います。
```
php$book->title           // Bookオブジェクトの title プロパティ
$query->where(...)        // クエリビルダの where メソッド
$this->user->name         // this の user の name
```
日本語だと「〜の」です。$book->title は「本の、タイトル」。

## `=>` は *「対応づける」 とき* に使います。用途は2つあります。
```
// 用途1：配列のキーと値の対応
[
    'id'   => $this->id,      // 'id' というキーに、この値を対応させる
    'name' => $this->name,
]

// 用途2：アロー関数の「引数 → 戻り値」の対応
fn ($x) => $x * 2             // $x を受け取ったら、$x * 2 を返す
```
- Resource の toArray() で毎行使っている => は用途1、
- fn () => は用途2

です。同じ記号ですが、配列の中か fn の後ろかで意味が変わります。

## == と => の違い

### == … 比較演算子（loose comparison / equality operator）
「左と右が等しいか？」を判定して true / false を返します。式なので、if の条件などで使います。
```
if ($book->genre_id == 3) {
    // genre_idが3なら実行
}

var_dump(1 == '1');   // true（型が違っても値が同じならtrue）
```
### => … 配列のキーと値を対応させる記号
判定は一切しません。真偽値も返しません。配列リテラルや `foreach` の中だけで使う「対応付けの矢印」です。
```
$data = [
    'title' => 'Laravel入門',   // キー'title'に値を紐づけるだけ
];
```

### 決定的な違い
|   |種類|返すもの|使える場所|
|---|---|---|---|
|`==`|演算子|`true`/`false`|式が書けるところ全般（`if`、`while`など）|
|`=>`|構文の一部|何も返さない|配列リテラル、`foreach`、`match` の中だけ|
つまり `if ($a => $b)` は文法エラーですし、`['title' == 'value']` と書くと「'title'と'value'を比較した結果（false）」が値になってしまい、意図とは全く違うものになります。

>`==` は「比べる」、`=>` は「結びつける」

と覚えると混ざりにくいです。なお比較は型まで見る `===` を使うのがLaravelでも推奨されます。
