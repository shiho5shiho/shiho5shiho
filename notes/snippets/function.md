# function()とは？
## function() = 処理をまとめて名前をつけたもの
料理でいうと **レシピ**です。作るたびに手順を思い出すのではなく、レシピに名前をつけておいて「カレー作って」と呼ぶだけで済む。
```
// 定義（レシピを書く）
function greet($name) {
    return "こんにちは、{$name}さん";
}

// 呼び出し（レシピを使う）
echo greet('okdSH');  // こんにちは、okdSHさん
```
### 3つの要素だけ覚えれば十分です。
|要素|意味|上の例|
|---|---|---|
|引数|外から渡す材料|`$name`|
|処理|中でやること|文字列を組み立てる|
|戻り値|呼び出し元に返す結果|`return` した文字列|


「引数を受け取って → 処理して → return で返す」が基本形です。

### なぜ使うのかは3つ。
 - 同じ処理を何度も書かなくて済む（再利用）
 - 修正が1か所で済む（保守性）
 - 名前を見れば何をするか分かる（可読性）。


## 無名関数（匿名関数 / クロージャ）
**名前をつけずにその場で作る関数** です。

「一度しか使わないから、わざわざ名前をつけるほどでもない」というときに使います。
```
$greet = function ($name) {
    return "こんにちは、{$name}さん";
};

echo $greet('田中');
```
変数に代入できる = 関数を「値」として扱える、というのが最大のポイントです。
>[!Tip]なぜ必要か：関数に処理を渡せる
Laravel でよく見るこの形が、まさにそれです。
```
$books = Book::where(function ($query) {
    $query->where('title', 'like', '%PHP%')
          ->orWhere('author', 'like', '%PHP%');
})->get();
```
`where()` に「どう絞り込むか」という処理そのものを渡している。名前をつける意味がないので無名関数にしています。

## PHP の落とし穴：`use`
無名関数は、外側の変数を**自動では見てくれません** 。
```
$keyword = 'Laravel';

// ✖ $keyword が undefined
$books = Book::where(function ($query) {
    $query->where('title', 'like', "%{$keyword}%");
})->get();

// ○ use で明示的に渡す
$books = Book::where(function ($query) use ($keyword) {
    $query->where('title', 'like', "%{$keyword}%");
})->get();
```
この「外の変数を閉じ込める(close over)」性質からクロージャと呼ばれます。

## fn() =>: アロー関数（PHP 7.4〜）
1行で済む場合の短縮形。こちらは use 不要で外の変数を自動で参照します。
```
$titles = $books->map(fn($book) => $book->title);
```
`fn` は式ひとつだけ、`return` も書かない、というルールです。

>[!Tip] 「複数行なら function + use、1行なら fn」 

## まとめ
|書き方|名前|外の変数|書ける処理|`return`|主な用途|
|------|---|--------|---------|--------|-------|
|function name() {}|あり|見えない|複数行OK|必要|何度も使う処理。他から名前で呼べる|
|function () {}|なし|`use` で明示が必要|複数行OK|必要|その場限りの処理。複数行のとき|
|fn () =>|なし|自動で見える|1つの式のみ|不要（自動）|その場限りの短い処理|

> JavaScript も考え方はほぼ同じで、`function(){}` と `() => {}` の関係が PHP の無名関数とアロー関数に対応します。ただし JS は `use` なしで外の変数が見える点が違います。
